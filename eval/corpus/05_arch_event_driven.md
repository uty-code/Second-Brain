# 이벤트 기반 아키텍처(Event-Driven Architecture) 설계 명세

## 1. 개요
이벤트 기반 아키텍처(EDA)는 시스템 컴포넌트 간의 직접적인 동기식 호출(RPC, HTTP REST)을 지양하고, 시스템 내에서 발생한 상태 변화를 '이벤트(Event)'로 모델링하여 비동기적으로 발행 및 소비하는 분산 소프트웨어 아키텍처입니다.

## 2. 핵심 구성 요소
- **Event Producer**: 도메인 상태가 변경되었을 때 이벤트 객체를 생성하여 중계 플랫폼으로 전송합니다. 발행자는 어떤 컨슈머가 이벤트를 받는지 알지 못합니다.
- **Event Broker (Message Broker)**: 발행된 이벤트를 버퍼링하고, 토픽(Topic) 기반 라우팅을 수행하며, 장애 발생 시 재생(Replay)할 수 있도록 지속성(Persistence)을 제공합니다.
- **Event Consumer**: 특정 이벤트 토픽을 구독(Subscription)하여 비즈니스 로직을 비동기로 처리합니다. 필요에 따라 또 다른 후속 이벤트를 발행할 수 있습니다.

## 3. 동작 원리 및 흐름
1. 클라이언트가 주문 API를 호출하면, 주문 서비스는 DB에 주문을 저장한 후 `OrderCreated` 이벤트를 브로커에 발행합니다.
2. 결제 서비스와 재고 서비스는 `OrderCreated` 이벤트를 각자의 속도에 맞추어 독립적으로 소비합니다.
3. 서비스 간의 물리적 결합도가 완전히 제거되므로, 결제 서비스에 장애가 발생하더라도 주문 접수 자체는 중단되지 않습니다.

## 4. 장점과 한계
- **장점**: 컴포넌트 간 시간적·공간적 느슨한 결합(Loose Coupling), 트래픽 급증 시 버퍼링을 통한 배압(Backpressure) 조절, 유연한 수평 확장성.
- **한계**: 최종 일관성(Eventual Consistency) 수용 필수, 분산 환경에서의 디버깅 및 전체 트랜잭션 추적(Tracing) 난이도 증가, 이벤트 스키마 버전 관리 복잡성.
