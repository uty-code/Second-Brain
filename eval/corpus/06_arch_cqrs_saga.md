# CQRS와 SAGA 패턴을 활용한 분산 트랜잭션 아키텍처

## 1. CQRS (Command Query Responsibility Segregation)
전통적인 단일 데이터 모델은 쓰기(Command) 작업과 읽기(Query) 작업의 요구사항이 상충할 때 복잡도가 급증합니다.
CQRS는 명령 모델과 조회 모델을 분리하여 각 작업에 최적화된 데이터 저장소를 사용하도록 합니다.
쓰기 모델은 도메인 비즈니스 무결성을 엄격하게 검증하며 RDBMS에 정규화된 형태로 저장하고, 변경 사항은 이벤트를 통해 비동기로 읽기 전용 저장소(Elasticsearch, Read DB 등)로 프로젝션(Projection)됩니다.

## 2. SAGA 패턴 (분산 트랜잭션 관리)
마이크로서비스 환경에서는 각 서비스마다 독립적인 DB를 가지므로 전통적인 2PC(Two-Phase Commit) 트랜잭션을 적용하기 어렵습니다.
SAGA 패턴은 일련의 로컬 트랜잭션들의 체인으로 분산 트랜잭션을 구현합니다.
- **코레오그래피(Choreography)**: 각 서비스가 이벤트를 발행하고 다른 서비스가 이를 구독하여 연쇄적으로 트랜잭션을 수행.
- **오케스트레이션(Orchestration)**: 중앙의 SAGA 오케스트레이터가 참여 서비스들에게 명령을 내리고 상태를 관리.
만약 중간 단계에서 비즈니스 오류나 결제가 실패하면, 이전에 완료된 작업들을 되돌리기 위한 보상 트랜잭션(Compensating Transaction)을 역순으로 실행하여 원자성을 사후 보장합니다.
